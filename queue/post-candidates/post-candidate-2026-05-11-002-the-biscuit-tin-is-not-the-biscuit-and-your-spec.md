# The biscuit tin is not the biscuit — and your spec is not the software

## Draft

A picture of a biscuit tin is not biscuits.

Obviously. You can't eat the tin. You can't taste the photo. No matter how accurate the description, the description is not the thing.

And yet.

Every week, in software projects everywhere, people treat the spec like the product. They argue about the spec as if shipping it would deliver value. They measure completeness of the spec as if that's the same as completeness of the software. They feel like the project is nearly done because the document is nearly done.

The map is not the territory. The biscuit tin is not the biscuit.

The only way to break this spell — and it is a spell — is to show working software, early and often. Not a prototype. Not a demo of the spec. Actual working software that does an actual thing for an actual user.

That's when people stop arguing about descriptions and start asking useful questions.

That's when "exact match" thinking gives way to "what actually works" thinking.

Until then, everyone is eating the tin.
