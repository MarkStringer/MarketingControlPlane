## Draft

I've been developing a show for Edinburgh Fringe about writing. The central idea keeps bleeding into how I think about software projects.

The idea is this: there are no mirrors, only prisms.

You cannot observe anything without transforming it. There is no neutral recording. Every person who looks at a project — a user, a stakeholder, a developer, a manager — is looking through their own prism. What they see is real. It's just not the same thing.

In the show, this is about writing. Your distortions are not a flaw. They're the reason to write. Nobody else sees it quite the way you do.

In a software project, the same logic applies — but most project thinking pretends otherwise.

We write specifications as if they can capture reality exactly. We draw diagrams as if everyone will read them the same way. We run kick-off meetings and assume shared understanding was achieved.

It wasn't. Everyone left with a different prism.

The map is never the territory. A description is not the product. The thing you imagine and the thing you build are not the same thing — and the gap between them is not a failure of communication. It's just the nature of the medium.

The smarter move is to stop pretending the prisms don't exist and start designing for them. Show working software early. Get different people looking at the same thing. Use the fact that perspectives differ.

Point of view isn't the problem. Pretending there's only one is.
